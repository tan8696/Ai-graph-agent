# Project Instructions & Hackathon Requirements

This document records all instructions, guidelines, and hackathon rules provided for the **Graph Brain** project, along with their implementation status.

---

## 1. Official Hackathon Rules & Guidelines

### Rule 2: Primary Technology Requirement
* **Rule**: FalkorDB must be the primary graph database in your project, and it must support a central part of what the product does.
* **Implementation**: FalkorDB is the sole knowledge base, topology storage, and multi-agent coordination medium. Services, dependencies, teams, engineers, tickets, decisions, incident playbooks, episodes, and conversations all live in FalkorDB.

### Rule 3: Real Work (Not Decoration)
* **Rule**: The graph has to do real work. A visualization drawn on top of ordinary storage does not qualify: if the product still works once FalkorDB is taken out, the graph is decoration rather than the thing the product runs on.
* **Implementation**: The system fails completely without FalkorDB. Every tool in `tools.py` directly executes parameterized Cypher queries over MCP. The Triage and Remediation agents have isolated LLM context windows and coordinate exclusively through the state machine of the `(:Incident)` node in FalkorDB. PageRank, multi-hop dependency traversals (`[:DEPENDS_ON*1..6]`), and customer impact paths are computed directly by FalkorDB's graph engine.

### Rule 4: Flexible Deployment
* **Rule**: Run FalkorDB however suits you: Docker, a self-hosted instance, and FalkorDB Cloud are all accepted, and you may use any language, framework, frontend, or deployment platform alongside it.
* **Implementation**: Docker Compose (`docker-compose.yml`) provides local 1-command startup on ports 6379 and 3000 (browser UI). FalkorDB Cloud is supported via `FALKORDB_URL=redis://...` in `.env`. The app runs on Python 3.11+ (FastAPI + SSE) with a vanilla HTML/CSS/JS + Cytoscape.js frontend.

### Rule 5: Challenge Tracks
* **Rule**: The challenge is open-ended within three tracks:
  1. *Agents That Act on Connected Data*
  2. *Agent Memory and Coordination*
  3. *Company Brain*
  You may enter any or all of them, and you must name every track you are entering when you submit.
* **Implementation**: Graph Brain is entered into **all three tracks**:
  - **Track 1**: Autonomous agents execute multi-hop blast radius traversals, PageRank criticality ranking, customer impact path tracing, and expert path discovery over MCP.
  - **Track 2**: Triage and Remediation agents coordinate without shared prompt context via the `(:Incident)` graph node. Three tiers of graph memory: Conversational, Episodic, and Self-Mutating Procedural runbooks.
  - **Track 3**: A unified enterprise knowledge graph connecting organizational ownership, architectural decision lineage, documentation, and live runtime updates.

### Rule 6: Allowed Data Only
* **Rule**: Your project must use data you are allowed to use: public, synthetic, or your own. Do not load private, login-protected, paywalled, personal, or otherwise restricted information into your graph.
* **Implementation**: 100% synthetic, deterministic data generated by `seed.py`. Generates fictional tech company `acme` with 30 microservices, 15 engineers, 40 tickets, 6 decisions, and 6 incident playbooks. Zero proprietary data.

### Rule 7: Submission Timeline
* **Rule**: Hackathon runs from **October 15, 12:01 AM IST to October 18, 11:59 PM IST**. Submissions close at the end of that window.

## 2. Mandatory Submission Deliverables

Every submission must include:
1. **A public source-code repository**: Clean repository with `.gitignore`, `.env.example`, no leaked keys.
2. **A README with setup instructions and your graph data model**: Comprehensive `README.md` with visual Mermaid diagrams, entity definitions, and step-by-step setup guides.
3. **The Cypher queries or graph algorithms the product depends on**: Full Cypher statements documented for PageRank (`algo.pageRank`), multi-hop dependency traversals (`[:DEPENDS_ON*1..6]`), shortest customer paths, expert evidence paths, decision lineage, runtime runbook rewiring, and counterfactual action sandboxing.
4. **A demo video showing the working project**: 4-act demonstration walkthrough script documented in `README.md`.
5. **A live deployment, or complete local setup instructions**: Automated test suite (`python test_graph.py`) passing with 100% assertions, plus clear local execution steps.
6. **The tracks you are entering**: Explicitly declared at the top of `README.md` and `PROJECT.md`.
7. **AI coding assistant disclosure**: Fully disclosed use of AI assistants (Antigravity IDE, Google Gemini) alongside human architecture design, testing, and verification.
8. **Technical understanding & defense**: Participant must understand and be able to explain the graph model, queries, architecture, and technical decisions.

## 3. UI, UX & Visual Design Instructions Given

### Instruction 1: Graph Animation, Speed & Zoom Navigation
* **Instruction**: *"the graph is super laggy make the graph animation sm0ooth and add some zoom effect when navigating the graph.add some animation and ui improvements that improves user experience but also make the website fast."*
* **Implementation**:
  - Optimized Cytoscape layout physics: reduced force simulation iterations (`numIter: 300`), enabled `animate: 'end'` to prevent per-frame render thrashing.
  - Added smooth camera zoom and pan animations when clicking nodes, citation pills, or toolbar zoom buttons.
  - Added visual HUD zoom indicator with pulse animation on zoom level changes.
  - Added silky cubic-bezier transitions for node hovering and focusing.

### Instruction 2: Graph Readability & Decluttering
* **Instruction**: *"make the graph dots small easy to read they are too cluteerd right now and make it so that user can understand the contents easily"*
* **Implementation**:
  - Shrunk node sizes to 10px–18px with distinct shapes and color accents per entity type (Service = circle, Person/Team = rounded rectangle, Incident = glowing diamond, Decision = hexagon, Ticket/Document = tag, Customer = outline box).
  - Truncated default node labels to `shortName` with subtle dark background pills.
  - Increased node repulsion and layout spacing in `cose` and tree layouts.
  - Edge relationship labels (`DEPENDS_ON`, `OWNS`, etc.) are hidden by default to remove visual clutter and only reveal on hover/highlight.
  - Implemented an informative, floating monochrome tooltip showing node type, name, tier, owner, and connected relationships.

### Instruction 3: Curved and Smooth Edges
* **Instruction**: *"make all the edges in the website curved and smooth"*
* **Implementation**:
  - In Cytoscape.js: Set `curve-style: 'bezier'` with `control-point-step-size: 40` and cubic-bezier transition curves for all graph edges and highlights.
  - In Website UI (CSS): Applied consistent rounded corners (`border-radius: 6px`, `8px`, `14px`, `999px`) across all cards, containers, buttons, search inputs, modal sheets, and pills.
